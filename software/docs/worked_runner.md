# Complete offline worked orchestration — source1.11.0

`worked_runner.run_offline(new_root, RunnerConfig, RunnerPorts)` composes the existing controller, producer, source outcome store, true CPC adapter, independent-rules/full-information comparisons and inventory-backed handoff in one explicit local run. It is **supplied-evidence offline software**, not a native connector, human authority verifier, scientific worked demo, JLA acceptance check or release service.

User instructions for this build forbid running the worked study/native system or revising the manuscript. Verification uses only inherited artificial padding/wire fixtures and new labeled synthetic engineering test assertions, never the22October pedagogical catalog or21October real-native reads. No old result/source/fixture is overwritten.

## Supplied API inputs

- `RunnerConfig`: typed LedgerScope/ControllerContext, ordered immutable EpisodePlans, purpose, supported transport evidence class, explicit maximum operations/observations/publication attempts. Ready-looking declarations do not prove actual rights/window/profile validity. Unresolved controller facts are refused before root creation. Scope epoch must match context. Defaults are bounded; at most96publication stores fit the inherited report inventory domain.
- `EpisodePlan(episode_ref,logical_resource,config_id,task_value_digest,followup_value_digest,publications=1,outcome_owner_ordinal=1)`: only supported hint/answer resources and five configured tuples. Outcome owner is fixed prospectively, never chosen from score/verdict/last-valid response. That is bookkeeping, not causal attribution or scientific approval.
- `RunnerPorts.operation(OperationRequest)->OperationInput`: receives the already persisted operation ID/kind/watermark and expected digest. Returns a known/unknown completion declaration and up to3immutable `ObservationInput(slot_ms,raw,reported_exit_code,reported_close_confirmed)`. It must supply byte transports, not open a source. All returned raw items are retained, including a later bad/unused observation. The controller validates the actual supplied receipt IDs; the runner never patches them to match expected values. WAIT/duplicate labels remain distinct. These are supplied labels/status claims, **not actual measured subprocess durations or native completion proof**.
- `RunnerPorts.help_inputs(HelpRequest)->HelpInputs`: receives an already allocated invocation_ref as well as attempt/episode/config. Provides external signed assignment/resolution plus ProducerPolicy, exact prompt/generation/catalog/binding, optional explicit clock. Signatures/keys/profile authority are external operator declarations, not generated by the runner. Production code imports no fixture setup/signer. Preparation failures retain and settle the received invocation as known NONE before failing; actual producer uncertainty is never relabeled zero publication.
- `RunnerPorts.sign_outcome(OutcomeRequest)->bytes`: after selected-source derivation provides the actual derived outcome key and exact producer exposure; caller returns the signed metadata outcome. No value/score is put on the CPC wire. The runner retains returned raw bytes and submits the assembled chain to the real core; it does not infer ADMIT from a fixture name.
- `RunnerPorts.admission_context()->AdmissionContext` supplies a separately obtained profile/key/validation-time context once after all selected source outcomes. Keys remain in memory; inherited context receipts export fingerprints only. `RunnerPorts.recipe` must be an explicit typed OutcomeRecipe, not the unapproved22October recipe with null review/rights/presentation.

Ports are **trusted in-process application callables**, not user-named dynamic plugins. Their declarations cannot attest native truth or human permission. An explicit cooperative audit hook blocks socket, subprocess, shell and sqlite connection events while `run_offline` is active. It is process-wide while active and intentionally not a sandbox against malicious Python, filesystem exfiltration, hostile same-user code or observer collusion. Use a dedicated process when an application also needs unrelated concurrent networking. Import/plan inspection does not install the hook or perform writes.

## Integrated sequence and failure accounting

One controller and one OutcomeStore own all episodes. Each TASK and FOLLOWUP has an opportunity/operation before its supplied input callback. Reported known completion and raw transport precede controller ACK; unknown/nonzero/close-uncertain/HOLD never opens help or the next operation. Repeated supplied observations retain ingestion multiplicity without fabricating extra attempts. No native submit, helper process, HTTP, polling or timing scheduler is implemented here.

Each help request is allocated before external preparation. New optional `producer.produce(..., preallocated_invocation_ref=...)` only adopts that exact same-attempt/resource/config RECEIVED/unsettled/unpublished invocation. Invalid/reused/foreign references are refused without new invocation or mutation. Legacy callers omit it and keep the prior behavior.

Producer publication remains the existing real local durable-file boundary with actual capture/sign/commit/release receipts. Every call gets a new producer root. The second E3publication is retained as producer/native publication evidence, but only the explicitly chosen owner is derived once into the selected-source outcome/full chain. All episode/publication metadata is written in `episode_ledger.json`; no-clone ownership remains enforced by OutcomeStore and native ambiguity remains HOLD in downstream mapping.

After the final saved analysis, all raw chains go through CPCAdapter; all comparison arms receive the same CommonEvidence/native-prefix/selected-source/auxiliary evidence. B0/B2 may match CPC exactly; B1 remains ablation. A true API failure stays unresolved and may prevent adapter export, not become a fake core disposition. Native, invocation, publication, core and external grains are never assumed equal.

The runner captures typed controller/outcome/adapter/producer inventories, builds both restricted and reader-candidate handoffs and verifies deliveries plus read-only controller/outcome replay. Producer captures/recipe bytes are available to every full-information arm. Source-only publications and all failed/pending/unknown states remain visible; no outcome clone or filtering invalid rows to rescue a singleton.

## Outputs

Fixed new-root paths: `STARTED.json`, `events/`, `received/`, `controller/`, `outcomes/`, `producers/`, `admission/`, `comparison.json`, `common_receipt.json`, `controller_view.json`, `outcome_view.json`, `adapter_view.json`, `episode_ledger.json`, `handoff_report.json`, `handoff/RESTRICTED`, `handoff/READER_CANDIDATE`, `RUNNER_RESULT.json`, `RUNNER_MANIFEST.json`; failures add a separate `RUNNER_FAILURE.json` and keep all existing partial roots.

`RunnerResult.to_mapping()` normalizes nested immutable values before serialization, preserving the lesson from the21October stdout failure. Terminal persistence is outside the pipeline failure handler; a late writer/manifest failure must not rerun the pipeline or overwrite an existing result. A saved result alone is not a completed/verified delivery: call `verify_worked_output(root)` and retain the calling process exit status. No writable reopen/recovery/resume/automatic retry is supplied.

Statuses are local engineering scope: COMPLETED with RECONCILED_DECLARED_SCOPE; DIAGNOSTIC_INCOMPLETE when downstream evidence remains incomplete; FAILED with actual phase/exception type and partial counters. Callback exception text, key bytes and raw payloads are never printed into the failure summary. Raw input files remain restricted to the local owner; neither receipt/status/hash nor reader-candidate delivery grants public release or scientific validity.

## Strict bounds and verification details

The full workflow labels derived from episode_ref (including the longest `:FOLLOWUP`) and run/store suffixes are validated before writes. Minimum declared observations cover at least one observation for every task/followup; actual WAIT consumption can still exhaust a legal budget and stops without another request. Scope.purpose is a bookkeeping label; when it is explicitly one of the two source evidence labels it must match evidence_class. STARTED records both independently, never upgrading source truth through a generic purpose name. JSON pending_facts must be an actual array, not an empty string normalized to readiness.

At most64MiB of returned input bytes is retained by the orchestrator. Before producer auxiliary files are read, the common native/raw/exposure/external/context/recipe footprint is checked and deducted from its64MiB common-evidence budget. Regular-file sizes and total count are checked incrementally before reads; changed/oversized/nonregular files stop, not truncate. Own raw input, manifest and output paths are exclusive regular single-link files; plan/manifest readers refuse FIFO/symlink leaves before reading. No hostile-filesystem/distributed-custody claim follows.

An additional supplied NO_MATCH/WAIT after a positive capture is treated as external source-progress conflict: prior capture/raw data are retained but no help/new operation progresses. Supplied duplicates remain separate ingestions. Failure accounting distinguishes retained complete chains (`complete_core_inputs`) from actual submitted adapter rows (`core_inputs_submitted`); the former increments only after durable chain retention and the latter from the adapter's actual received ledger. Episode completion increments only after its durable event. Prepared-but-not-submitted inputs cannot masquerade as received core rows.

`verify_worked_output` validates the closed result schema, exact offline/false boundary flags, successful status↔report status/phase consistency, and matching separate failure receipt for FAILED, in addition to full file inventory/hash and handoff verification. Its verdict is local byte/schema consistency only, not native acquisition, owner permission, scientific value or public release.

`source_only_publications` is derived from all known published invocation IDs minus owners of durable prepared complete chains, including failures before an outcome exists. `publication_uncertain` remains separate, and `retained_chains_not_submitted` distinguishes durable chain bytes from actual adapter receipt. A reporting/retention failure cannot erase an earlier designated publication from these counters.

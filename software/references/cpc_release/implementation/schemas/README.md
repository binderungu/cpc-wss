# Restricted offline schema interface

These are executable structural schemas for prospective contract 2.0.1. They are not conformance results, actual profiles, key fixtures, or artifact registries. The bundled evaluator implements only the keywords below; the `$schema` annotation identifies the schema vocabulary and does **not** claim complete Draft 2020-12 compliance.

Supported keywords: `$schema`, `$id`, `$defs`, `$ref`, `title`, `description`, `type`, `properties`, `required`, `additionalProperties`, `patternProperties`, `propertyNames`, `items`, `minItems`, `maxItems`, `minProperties`, `minLength`, `maxLength`, `minimum`, `pattern`, `format`, `enum`, `const`, `anyOf`. Types are the single names object, array, string, integer, boolean and null. Type arrays, tuple items, boolean schemas and unlisted keywords are unsupported. Bounds are nonnegative integers. Patterns use the Python standard-library regular-expression engine; shipped expressions use the shared ECMA/Python subset. Formats are `identifier`, `ascii-identifier`, `date-time` and `namespaced-key`, asserted rather than treated as annotations.

All definitions are checked before instance evaluation. References are offline schema filenames and restricted `#/$defs/name` pointers; remote/absolute/path-traversing references fail closed. Unknown keywords, formats and unsupported definitions produce a schema-definition error; none are silently ignored. `check_schema_definitions()` is syntax/reference checking, not CPC conformance. Unknown instance field names are redacted to `[unknown]`; keys in map schemas use `[field]`. Diagnostic codes and messages omit instance values.

`validate_named(value, name, path='$', max_identifier_chars=256)` (the bound is keyword-only) and `validate_instance(value, schema, path='$')` return diagnostic dictionaries. Canonical names are filename stems. `record` unions the four closed record classes, and `chain` applies that union to every member. Per-class names are `assignment_record`, `resolution_record`, `exposure_record`, `outcome_record`. Proof wrappers and bodies are named `launch_attestation`, `commitment`, `usage_attestation`, `release_attestation` and the corresponding `_body` stems. There are separate closed artifact, measured-component, integrity, profile, result and admitted-export schemas. `extensions` permits explicitly namespaced metadata keys and recursive supported metadata types; the operator allowlist and privacy policy remain separately required.

Well-typed condition, context, version, consent-state, evidence-mode, algorithm and release-boundary strings remain semantic domains. Their authorization is checked under the trusted external profile and semantic rules; schemas do not impose A/B/C/D or conflate unauthorized domain values with malformed input. `record_type` is a structural class discriminator. Empty records represent missing evidence and are structurally allowed.

## Frozen external profile representation

`validate_profile(profile, validation_time, key_registry)` validates separately supplied operator configuration and returns only C01/ERROR_CONFIG diagnostics. No profile is loaded from a chain. The trusted time is an RFC3339 string. `profile_state='frozen'` and the required `freeze_timestamp` represent the explicit immutable state; the freeze instant must not be later than trusted validation time. Profile identity must name contract `2.0.1` and schema `cpc-2.0.1`. There are no defaults or profile/key instances in this directory.

Exact required field names are:

```json
["profile_id","profile_version","contract_version","schema_version","experiment_id","experiment_version","expected_audience","deployment_id","context_id","scope","assignment_policy_version","resolver_version","mapping_version","consent_policy_version","observer_clock_id","release_boundary","profile_state","freeze_timestamp","conditions","resource_condition_map","namespace_policy","record_issuers","proof_issuers","issuer_key_policy","permitted_purposes","consent_authority_refs","artifact_registry","required_measured_components","component_canonicalizations","fallback_permissions","extension_keys","privacy_denylist","input_limits"]
```

`record_issuers` has assignment/resolution/exposure/outcome keys. `proof_issuers` has launch_attestation/commitment/usage_attestation/release_attestation keys. `issuer_key_policy` maps each logical issuer to a key ID. External registry values are ASCII strings or bytes with a nonempty `SYNTHETIC_ONLY_` suffix; they are fixture material, never production credentials. Assignment and launch share their authority, exposure and commitment share runtime authority, usage and release share observer authority; the five assignment/launch, resolver, runtime, outcome and observer logical key IDs must be distinct.

`namespace_policy` maps names to closed `{role, required, mapping}` entries. At least one authoritative namespace is required; mapped values must belong to `conditions`; descriptive mapping is empty. Artifacts contain exactly prompt/generation/ui/corpus/retriever/index/model/policy entries, with prompt and generation measured and the remaining six declared. Canonicalization labels are the policy's `raw-bytes consumed` and `cpc-json-v2 object consumed`. `fallback_permissions` maps authorization references to `{condition, artifact_versions}`. Extensions are registered namespaced strings. Privacy denylist names are exact normalized leaves (casefold, then retain alphanumeric characters). Input limits cannot exceed 1048576 bytes, 16 records, depth 32 and 256 identifier characters; positive record and depth limits may be stricter than a complete four-record nested shape; inputs exceeding them are ERROR_INPUT under contract section2, not ERROR_CONFIG.

Identifier-bearing map names are validated through `propertyNames`, with redacted `[field_name]` paths. Per-profile bounds apply to identifier values and dynamic names; encoded digests/MACs and fixed field names retain their separate representation rules.

Depth under CPC2.0.1 is root0 with one edge to each object key/value or array item; scalar leaves and empty containers count. The bound is inclusive and applies to the full decoded chain, not operator configuration. API iter_json_nodes and json_depth share this definition; the evaluator remains restricted, not full Draft2020-12.
